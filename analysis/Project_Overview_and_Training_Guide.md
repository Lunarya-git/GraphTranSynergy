# GraphTranSynergy - Comprehensive Project Analysis & Guide

This document serves as a complete, in-depth guide to the `GraphTranSynergy` repository. It provides a highly organized breakdown of the directory structure, data processing pipelines, model architecture, and training configurations. 

Any new researcher or developer looking at this project should start here to understand how the components interact.

---

## 📂 1. Directory Structure Overview

The repository is structured to separate data, models, utility scripts, and training pipelines.

```
GraphTranSynergy/
├── analysis/                     # (You are here) In-depth project documentation and analysis.
├── data/                         # Contains all raw and processed datasets (extracted from data.7z).
│   ├── processed/                # PyTorch Geometric (.pt) graph data generated during preprocessing.
│   ├── result/                   # Outputs of model training (saved models, metrics, predictions).

├── model/                        # Contains neural network architectures (extracted from model.7z).
│   └── GraphTransformer.py       # Core Graph Transformer model definition.
├── .venv/                        # Python Virtual Environment (generated by setup script).
├── creat_data_DC.py              # Script to generate PyTorch Geometric dataset from SMILES and cell features.
├── load_data.py                  # Script to load data and map SMILES to graphs.
├── preprocess_data.py            # Main entry point for data preprocessing (builds .pt files).
├── requirements.txt              # Python dependencies list.
├── roc_auc.py                    # Utility for calculating ROC/AUC and other metrics.
├── run_one_epoch.py              # Training script hardcoded to run exactly 1 epoch (for quick testing).
├── setup_and_run.ps1             # PowerShell script to fully setup the environment, extract data, and run 1 epoch.

└── utils_test.py                 # Core utilities: graph encoding, PyG dataset class (`TestbedDataset`), early stopping.
```

## 📊 2. Data Information (`data/` folder)

The data pipeline focuses on converting chemical representations (SMILES strings) and cell line features into graphs and tensors suitable for deep learning.

### Raw Data (Extracted from `data.7z`)
*   **`smiles.csv`**: Contains the SMILES string representations of the drugs.
*   **`new_cell_features_954.csv`**: Contains numeric features for various cell lines.
*   **`new_labels_0_10.csv`** (and similar label files): Contains the ground truth labels representing the synergy or interaction score between `drug1`, `drug2`, and a specific `cell`.

### Data Processing Pipeline
Data processing is handled primarily by `creat_data_DC.py` and `utils_test.py`.
1.  **Graph Construction**: SMILES strings are parsed using `rdkit`. Each atom becomes a node (with features like symbol, degree, implicit valence, etc., one-hot encoded), and chemical bonds become edges. This creates a directed graph via `networkx`.
2.  **Cell Line Features**: Cell line features are loaded and concatenated or processed alongside the drug graphs.
3.  **PyTorch Geometric Format**: The scripts use the `TestbedDataset` class (in `utils_test.py`) to convert these raw graphs and labels into `.pt` files.
4.  **Output Location**: Processed `.pt` files are stored in `data/processed/` (e.g., `new_labels_0_10_drug1_train.pt`).

## 🧠 3. Model Information (`model/` folder)

*   **`GraphTransformer.py`**: The core deep learning model. It utilizes a Graph Transformer architecture to process the molecular graphs of `drug1` and `drug2`, likely integrating the `cell` line features to predict drug synergy.
*   The model expects graph data prepared via `torch_geometric.data.DataLoader`.

## ⚙️ 4. Training Configurations & Scripts

The repository offers multiple scripts for training and testing, each with specific hyperparameters.

### A. Main Training (`training_GraphTransformer.py`)
This is the primary script for training the Graph Transformer with 5-fold cross-validation.
*   **Target Data**: `new_labels_0_10`
*   **Validation Strategy**: 5-Fold Cross Validation. Data is randomly shuffled and split (80% train, 20% test per fold).
*   **Hyperparameters**:
    *   **TRAIN_BATCH_SIZE**: 256
    *   **TEST_BATCH_SIZE**: 256
    *   **LEARNING_RATE (LR)**: 0.0005
    *   **NUM_EPOCHS**: 100
    *   **LOG_INTERVAL**: 20
*   **Optimizer**: Adam
*   **Loss Function**: CrossEntropyLoss (`nn.CrossEntropyLoss()`)
*   **Outputs**: Saves the best model `.model`, predictions `.csv`, and metrics `.txt` per fold in `data/result/sun_pre_test/GraphTransformer/`.

### B. Independent Validation (`training_validation.py`)
This script is designed for training on specific datasets and testing on independent datasets (e.g., leave-tissue-out or leave-drug-out scenarios).
*   **Target Data**: Loops over specific datasets (e.g., `c00`, `c11`, `c22`, `c33`, `c44`).
*   **Hyperparameters**:
    *   **TRAIN_BATCH_SIZE**: 256
    *   **TEST_BATCH_SIZE**: 256
    *   **LEARNING_RATE (LR)**: 0.0001 *(Note: Lower than the main training script)*
    *   **NUM_EPOCHS**: 1000
    *   **LOG_INTERVAL**: 20
*   **Outputs**: Saves metrics and models in `data/result/sun_pre_test/`.

### C. Quick Test Run (`run_one_epoch.py`)
A modified version of the main training script designed for rapid testing and continuous integration.
*   **Hyperparameters**: Identical to `training_GraphTransformer.py`, **EXCEPT** `NUM_EPOCHS` is hardcoded to `1`.
*   **Purpose**: Used by the setup script to verify that the environment, data loading, model forward/backward passes, and metric calculations work without waiting for a full 100-epoch training cycle.

## 📈 5. Evaluation Metrics

Across all training scripts, the model's performance is evaluated using standard classification and ranking metrics from `sklearn.metrics`. During prediction, the output logits are passed through a Softmax function.

Metrics calculated include:
1.  **AUC (ROC-AUC)**: Area Under the Receiver Operating Characteristic Curve.
2.  **PR-AUC**: Precision-Recall Area Under Curve.
3.  **ACC**: Accuracy.
4.  **BACC**: Balanced Accuracy.
5.  **PREC**: Precision.
6.  **TPR (Recall)**: True Positive Rate / Sensitivity.
7.  **KAPPA**: Cohen's Kappa score (measures inter-rater reliability).

The model state is saved (checkpointed) whenever a new **Best AUC** is achieved on the test fold/set.

## 🚀 6. Setup and Execution Pipeline

The project includes an automated setup script for Windows (`setup_and_run.ps1`) which performs the following:

1.  **Environment**: Creates a Python virtual environment (`.venv`).
2.  **Dependencies**: Upgrades pip and installs packages from `requirements.txt`. Crucially, it installs `torch` with CUDA 12.4 support, and corresponding `torch-geometric` components (`torch-scatter`, `torch-sparse`, `torch-cluster`).
3.  **Data Extraction**: Uses 7-Zip to extract `data.7z` and `model.7z`.
4.  **Directory Creation**: Ensures output paths like `data/result/sun_pre_test/GraphTransformer/` exist.
5.  **Preprocessing**: Runs `preprocess_data.py` to generate the `.pt` graph files from raw CSVs.
6.  **Verification Run**: Executes `run_one_epoch.py` to perform a 1-epoch test run across 5 folds to ensure the pipeline is fully operational.

**To run the full pipeline from scratch (Windows):**
```powershell
powershell -ExecutionPolicy Bypass -File setup_and_run.ps1
```
